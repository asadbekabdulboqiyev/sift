How a Site Reaches a Full 100/100

A practical, visual guide showing exactly where to run the audit, what each score means, and which configuration changes (with code locations) produce a legitimate 100/100 result when measured evidence supports it.

Important: 100/100 is an outcome of real measurements (security checks, measurable load/resilience, complete evidence) under the selected mode and window — not a value to force. Only test systems you own or have explicit written permission to test. Nothing here authorizes unauthorized testing.

1) What the 100/100 Score Means

In a completed Standard Sift 360° audit, the scorecard reports component scores and an overall result. A full score requires all components to be supported by evidence.

Security · 100No security findings from executed checks (headers/TLS/misconfiguration/lightweight OWASP surface).
Resilience · 100No failure-threshold breach under measured load (e.g. error/latency within thresholds in the test window).
Capacity · 100Capacity is measurable with no adverse/breach evidence; load is not blocked/unmeasurable.
Evidence · 100Required stages complete with usable evidence (scan not partial, active load measured when required).

3) Where and What to Change (Exact Code/Config)

To remove security findings and produce stable, measurable behavior, apply recommended protections consistently to audited endpoints. Below are the concrete changes used by the 100-point demo target.

3.1 Security headers — remove header/misconfiguration findings Security 100

Where to change: your HTTP middleware/response headers (reverse proxy or app).
Demo implementation: examples/perfect_demo_site/main.go → securityHeaders(next http.Handler).

Set the following headers on responses (tune CSP to your real asset/script needs; keep it as strict as possible):

func securityHeaders(next http.Handler) http.Handler {
  return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    w.Header().Set("X-Content-Type-Options", "nosniff")
    w.Header().Set("X-Frame-Options", "DENY")
    w.Header().Set("Referrer-Policy", "no-referrer")
    w.Header().Set("Permissions-Policy", "geolocation=(), microphone=(), camera=()")
    w.Header().Set("Content-Security-Policy",
      "default-src 'self'; style-src 'unsafe-inline'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'")
    w.Header().Set("Cache-Control", "no-store")
    next.ServeHTTP(w, r)
  })
}

3.2 Stable, correct endpoints — complete evidence Evidence 100

Where to change: your routing/handlers.
Demo implementation: examples/perfect_demo_site/main.go → handlers for / and /health.
  • Ensure the audited URL is reachable and returns consistent, valid responses during the run.
  • Provide a lightweight health/content endpoint; avoid intermittent 5xx/timeouts.
  • Apply the same security headers to audited endpoints (not only the homepage).
mux.HandleFunc("/health", func(w http.ResponseWriter, r *http.Request) {
  w.Header().Set("Content-Type", "application/json")
  _ = json.NewEncoder(w).Encode(map[string]string{
    "status": "ok",
    "service": "perfect-demo-site",
  })
})

3.3 Capacity & resilience — measurable, no breach Capacity/Resilience 100

Where to change: server/runtime sizing, reverse proxy/WAF/rate-limit rules, and application performance.
  • Run in Standard mode with authorization so active load is measured (Passive skips load by design).
  • Do not block the audit traffic path with WAF/bot/401/403/429 in a way that makes capacity unmeasurable for the in-scope test.
  • Keep error rate and latency within thresholds during the test window (optimize hot paths, right-size resources, tune timeouts).
  • “No breach within the audit window” is measured evidence, not a guarantee under higher/different load.

4) Checklist for a Legitimate 100/100

  • Scope Authorized target, correct mode, defined window
  • Security Recommended headers/TLS configured consistently, 0 findings
  • Stability Target reachable and stable for the full run
  • Standard Active load measurable (not blocked/skipped), no breach
  • Evidence No partial/unavailable stages; report sealed (signature/cert/hash)
  • Honesty Interpret as measured results for this run, not a lifetime guarantee
